# Risk Orchestrator — командный MVP

Прототип модуля управления процессами оценки рисков для турнира по продуктовому программированию.

## Быстрый запуск

Нужен Python 3.10+.

```bash
git clone https://github.com/rim-3483/product-programming.git
cd product-programming
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Откройте адрес, который покажет Streamlit, обычно http://localhost:8501.

## Проверка

```bash
python -m pytest -q
```

## Демонстрация

Нажмите «Добавить четыре тестовых процесса». A и C выполняются одновременно, B и D ждут ресурса A. Завершите A, и следующая ожидающая задача сможет запуститься. Здесь «выполнение» — **имитация**, без реальных вычислений.

## Структура и ответственные

| Путь | Назначение | Роль |
| --- | --- | --- |
| `docs/requirements.md` | Анализ и требования | Аналитик (dev-1) |
| `src/orchestrator.py` | Очереди и захват ресурсов | Backend (dev-2) |
| `app.py` | Streamlit-интерфейс | UI (dev-3) |
| `src/simulator.py`, `tests/` | Сценарии и тесты | Тестировщик (dev-4) |
| `requirements.txt`, интеграция | Сборка и демо | Интегратор (dev-5) |

## Работа в команде

Работайте в своих ветках `dev-1`…`dev-5`, перед началом обновляйте их из `main`. Изменения переносите в `main` через Pull Request после проверки. Не делайте force-push в чужие ветки.

## Важно: границы MVP

- Оркестратор и данные хранятся в памяти одной Streamlit-сессии.
- Для нескольких независимых пользователей **нет общей очереди и глобальных блокировок**.
- Задачи пока не исполняются фоновыми воркерами — их завершение подтверждают вручную.
- Для выполнения полного конкурсного кейса нужно добавить общий backend, постоянное хранилище, реальных исполнителей и многопользовательские тесты.

Первые требования и ограничения подробно описаны в [docs/requirements.md](docs/requirements.md).
